INTRODUCTION                                    *markdown-extras-introduction*

vim-markdown-extras adds some spice to the built-in |ft-markdown-plugin| with:

Core editing:
- Toggle bold/italic/strikethrough with key mappings
- Create, follow, autocomplete and preview links
- Manage tables (align, format, insert/delete rows/columns)

Block operations:
- Toggle quoted and code blocks on/off
- Format paragraphs with |gq| or automatically on save

Organization:
- Create multiple index files for different subjects or contexts
- Toggle checkboxes in TODO lists with one keypress

Additional features:
- Render markdown to different formats with `pandoc`
- Format text with `prettier`

Perfect for note-taking! No special syntax required, just markdown.

==============================================================================
REQUIREMENTS                                    *markdown-extras-requirements*

Vim 9.0 is required.
You must set a |localleader| key and your |vimrc| shall include the following
lines:
>vim
  set nocompatible
  filetype indent plugin on
  syntax on
<
To enable the rendering feature, you need to install `pandoc`.
To automatically open the rendered files, Vim must have the |:Open| command.
To enable the formatting feature, you need to install `prettier` or any other
formatting program of your choice.

USAGE                                            *markdown-extras-usage*

To best way to explain this plugin is through some examples.

TEXT-STYLES

Open a markdown file and place the cursor on a word.
Hit `<localleader>biw` to change the text-style inside-the-word
to bold. Note that `iw` is a text-object.
Then, while letting the cursor on the bold text, hit `<localleader>r`
to remove it.

Next, visually select some text and hit `<localleader>s`.
To remove the strike-trhough, stay on the text and hit `<localleader>r`.

See |markdown-extras-mappings| for all the possible text styles.

LINKS

Place the cursor on a word and hit |<enter>|.
Select `Create new link` from the popup menu and point to an existing file
or just type a new file name.
If you created a new file, fill it in with some text and save it.
Hit |<backspace>| to go back to the previous file.

Next, place the cursor on the newly created link. Hit |K|.
Then, hit |<enter>| again to open the link.
The link can also be external URL:s, e.g. `https://example.com`.
If the link is a file, then |<S-CR>| open it in a vertical split
window.

Next, create few links and use `<localleader>n` and `<localleader>N` to
locate their position in the current buffer. When on a link, hit
`<localleader>r` to remove it.

You can also dynamically refer to links as you type.
For example, to trigger links auto-completion when you hit `[`, add the
following lines to your `~/.vim/after/ftplugin/markdown.vim` file:

```vim
    const mde_funcs_path = globpath(&rtp, 'lib/mde_funcs.vim')->fnamemodify(':h')
    import autoload $"{mde_funcs_path}/mde_funcs.vim" as mde_funcs

    setlocal completeopt=menu,menuone,noselect
    setlocal omnifunc=mde_funcs.OmniFunc
    inoremap <buffer> ][ ][<C-x><C-o>
```

In your current document, type `[foo][` and a popup menu with all the
available links shall appear.

In case of a markdown file with mixed inline and
reference-style links, you can convert the former to the latter by using
|:MDEConvertLinks| command.

Note: the links management only applies to links reported after the line with
`<!-- DO NOT REMOVE vim-markdown-extras references DO NOT REMOVE-->`.

LISTS

You can create lists or enumerations as in any markdown file.
However, the behavior of the |<enter>| key overrides the behavior of the
underlying |vim-markdown| builtin plugin.
If you want the standard |ft-markdown-plugin| behavior, then set
`g:markdown_extras_config['hack_CR'] = false` in your `.vimrc`.

You can check/uncheck the items in to-do list with `<localleader>x`.
It is possible to change how check-boxes
are rendered by setting the keys `empty_checkbox` and `marked_checkbox` of the
`g:markdown_extras_config` dictionary.
For example you can set `g:markdown_extras_config[marked_checkbox] = 0x2714`.
The value shall be a valid Unicode point value.

If you have `vim-outline` installed, then you can use `<localleader>o` to
display the unchecked items of the to-do list in a scratch buffer.

TABLES

Run |:MDETableInsert| 2 3 to insert a 2x3 table placeholder.
Edit any cell. Hit |<localleader>|F to format the table.

Place the cursor on any cell and hit |<localleader>|C. Write some text and
hit |<enter>|.

Finally, put some numbers in some cells. Visually select the table and hit
|<localleader>|S. Look at the command line.

See |markdown-extras-mappings| for more functions.

Note: delimiters are not part of standard markdown specifications. However,
they makes tables management more powerful.

FORMATTING

If available, |gq| use `prettier`, but you can use any format program by
setting the key `formatprg` of the `g:markdown_extras_config` dictionary.

However,`formatprg` key may be removed from the configuration dictionary in
future releases as one could directly set locally |formatprg|.

RENDERING

If you have `pandoc` installed, then |vim-markdown-extras| sets |compiler-pandoc|.
You can then use |:make| to render your buffer with `pandoc`.

To render and open the rendered file at once, you can use |:MDEMake| followed
by |<tab>| to select a target.

You can also pass arguments to `pandoc` via the key
`pandoc_args` of the |g:markdown_extras_config| dictionary.
You could for example set the following:
>vim
  g:markdown_extras_config = {}
  g:markdown_extras_config['pandoc_args'] =
    [$'--css="{$HOME}/dotfiles/my_css_style.css"',
    $'--lua-filter="{$HOME}/dotfiles/emoji-admonitions.lua"']
<

INDICES

In the same spirit of vimwiki, this plugin offer the chance of use different
indices, selectable by a popup. See |:MDEIndex| for more info.

CONFIGURATION       *markdown-extras-configuration* *g:markdown_extras_config*

The plug configuration is done through |g:markdown_extras_config| dictionary.
Be sure to create the empty dictionary `g:markdown_extras_config = {}` before
filling it with he various keys.

      Available keys:
        "use_pandoc"      Set to |true| if you want to use |compiler-pandoc|.
                          `pandoc` needs to be installed separately.
                          Default |true|.
        "pandoc_args"     List of arguments to be passed to |compiler-pandoc|.
                          Example:
                          >vim
                          g:markdown_extras_config['pandoc_args'] =
                            ['--css="path/to/my_css_style.css"', '--metadata',
                            'key=value']`
<
 "use_default_mappings"   Such a value is copied to |b:pandoc_compiler_args|.
			  Set to |true| to use the default mappings as
                          described in |markdown-extras-mappings|.
                          Default |true|.

        "use_prettier"    Set to |true| if you want to use `prettier` formatter.
                          `prettier` needs to be installed separately.
                          Default |true|.

        "use_nerd_fonts"  To set eye-candy check-boxes. Require some nerd-font
                          installed.
			  Default |false|.

        "smart_textstyle" Whenever possible, text styles are kept
                          consistent.
			  Default |true|.

        "empty_checkbox"  Glyphs to display for empty checkboxes. Requires
                          "use_nerdfonts" set to |true| and 'concealevel'
                          greater than 0.
			  Default: 0x25A2

        "marked_checkbox" Glyphs to display for marked checkboxes. Requires
                          "use_nerdfonts" set to |true| and 'concealevel'
                          greater than 0.
			  Default: 0x2714

        "fuzzy_search"    Fuzzy or exact search in the links popup.
                          Default: |true|.

"path_to_url_register"    Register used when running the |:MDEPathToURL|
			  command.
                          Default: 'p'.

"link_first_register"     Register used by link yank/delete/paste mappings
			  targeting the first link register.
			  Default: 'a'.

"link_second_register"    Register used by link yank/delete/paste mappings
			  targeting the second link register.
			  Default: 'b'.

"link_third_register"     Register used by link yank/delete/paste mappings
			  targeting the third link register.
			  Default: 'c'.

        "hack_CR"         Set to |false| for the standard behavior of <CR>.
                          Default: |true|.

"large_files_threshold"   If you have large files linked to your document,
			  then you may experience lags or malfunctioning in
			  the preview function.
			  This value sets the minimum value in bytes after
			  which a file is considered large.
			  If a file is considered large, then the behavior of
			  the plugin changes to accommodate possible lags
			  and malfunctioning.
			  The drawback in using such a feature is that the
			  preview and the opening of small files will also
			  be delayed due to the "large file check" procedure
			  is performed on every file.
			  To disable this feature, set this value to 0.
                          Default: 0.

"smart_table_format"      If |true| the table are formatted taking into
			  account concealed characters. If on the one hand
			  this makes the markdown source file more readable
			  when |conceallevel| is not 0, on the other hand
			  some markdown renderes may struggle in correctly
			  render the table. Also, internal delimiter rows
			  (visual separators inside a table body) are
			  preserved as-is.
			  Note: this is only a visual-preservation feature.
			  Cell helpers still assume regular markdown table
			  geometry (no real rowspan/colspan semantics).
			  Default: |true|

'table_updates_in_window' If |true|, tables updates happen in a split
			  windows. Otherwise, tables updates happen in popup.
			  Default: |false|

						*g:markdown_extras_index*
g:markdown_extras_index   list<string>, list<list<string>> or dict<string>.
			  If list<string>, contain the path of indices files.
			  If list<string<string>> the first element of each
			  item of the list is the alias, whereas the second
			  is the link.
			  If dict<string>, the values are the actual links
			  whereas the keys are aliases. In the popup menu only
			  the alias are displayed.
			  Default: empty


						  *markdown_extras_omnifunc*
You can autocomplete links in the current buffer by setting the 'omnifunc' to
`mde_funcs.OmniFunc` in your `~/.vim/after/ftplugin/markdown.vim` file.
If such a file does not exists, create it.

For example, to trigger links autocompletion when you hit `[`, add the following
lines to your `~/.vim/after/ftplugin/markdown.vim` file:
>vim
    setlocal completeopt=menu,menuone,noselect
    import autoload "mde_funcs.vim"
    setlocal omnifunc=mde_funcs.OmniFunc
    inoremap <buffer> [ [<C-x><C-o>
<

COMMANDS                                         *markdown-extras-commands*

                                                        *:MDEConvertLinks*
:MDEConvertLinks    Convert inline links into reference-style links.

                                                       *:MDESanitizeLinks*
:MDESanitizeLinks   Remove unreferenced numeric references from the
		    references section and renumber used references
		    sequentially from 1, updating in-text references.

                                                            *:MDEIndex*
:MDEIndex [{args}]  Open a popup with what is specified in {args}.
		    The type of {args} can be list<string>, list<list<string>>
		    or dict<string>. If no argument is passed, then
		    |g:markdown_extras_index| is considered.

                    Note: This feature is the same as |:PoptoolsIndex| in
                    vim-poptools plugin, although it originated for this
		    plugin.

		    Example:
		    >vim
		      :MDEIndex  # Uses g:markdown_extras_index
		      :MDEIndex [
			    'local/path',
			    'some%20url',
			    'function("some_Funcref")'
			  ]
		      :MDEIndex {
			    foo: 'local/path',
			    bar: 'some%20url',
			    baz: 'function("some_Funcref")'
			  }
		      :MDEIndex [
			    ['foo', 'local/path'],
			    ['bar', 'some%20url'],
			    ['baz', 'function("some_Funcref")']
			  ]
<
		    Or it can be used in a script, like for example:
		    >vim
		      def Foo()
			const my_index = {
			  foo: '/Users/ubaldot/home/Documents/foo.vim',
			  bar: 'https://example.com',
			  banana: 'function("g:Foo")'
			}
			execute $"MDEIndex {my_index}"
		      enddef

		      command! MyIndex Foo()
<
		    The string used in the various cases can be a local path,
		    a valid URL or a function reference.
		    In the latter case, the referenced function must be global
		    and shall take no arguments.

                                                            *:MDEMake*
:MDEMake            Invoke |:make| and |:Open| the rendered file. It requires
                    `pandoc`. Its behavior can be further customized through
                    the |g:markdown_extras_config| dictionary.

                                                            *:MDEPathToURL*
:MDEPathToURL       Convert the passed file name to a valid URL and store the
		    result in a register. The default register is 'p' but that
		    can be changed through the |g:markdown_extras_config|
		    dictionary.

                                                        *:MDEDefaultMappings*
:MDEDefaultMappings Display default_mappings.

                                                          *:MDETableInsert*
:MDETableInsert [nrows, ncols]
		    Insert a nrows x ncols table.
		    Default: nrows = 3, ncols = 2.
                                                        *:MDEReleaseNotes*
:MDEReleaseNotes    Show release notes.

MAPPINGS                                         *markdown-extras-mappings*


Text styles~
Text styles are Vim idiomatic. For example, if the following mappings are
defined:
>vim
 nnoremap <buffer> B <Plug>MarkdownBold
 xnoremap <buffer> B <Plug>MarkdownBold
<
and e.g. `Bi(` is used in normal mode, then all the text inside the
parenthesis becomes bold.
Along the same line, by visually selecting some text and hitting `B` make the
selection bold.

<Plug>MarkdownBold                Change text style to bold with ** delimiter.
                                  Default: `<localleader>b{motion}`

<Plug>MarkdownItalic              Change text style to italic with * delimiter.
                                  Default: `<localleader>i{motion}`

<Plug>MarkdownBoldUnderscore      Change text style to bold with __ delimiter.
                                  Default: None

<Plug>MarkdownItalicUnderscore    Change text style to italic with _ delimiter.
                                  Default: None

<Plug>MarkdownStrike              Change text style to strike-trhough.
                                  Default: `<localleader>s{motion}`

<Plug>MarkdownCode                Change text style to code.
                                  Default: `<localleader>c{motion}`

<Plug>MarkdownUnderline           Change text style to underlined.
                                  Default: `<localleader>u{motion}`

<Plug>MarkdownRemove              Remove text-styles, links, highlights, etc.
                                  Default: `<localleader>r`

<Plug>MarkdownAddHighlight        Highlight text. Note highlighting is not
                                  persistent.
                                  Default: `<localleader>h{motion}`

<Plug>MarkdownCodeBlock           Set code-block.
                                  Default: `<localleader>f{motion}`

<Plug>MarkdownQuoteBlock          Set quote-block.
                                  Default: `<localleader>q{motion}`

Links~
The following can be used for creating mappings related to links.

<Plug>MarkdownAddLink             Create a link. The key-binding shall be
                                  followed by a motion.
                                  Default: `<localleader>l{motion}`

<Plug>MarkdownGotoLinkForward     Jump to the next link in the current buffer.
                                  Default: `<localleader>n`

<Plug>MarkdownGotoLinkBackwards   Jump to the previous link in the current buffer.
                                  Default: `<localleader>N`

<Plug>MarkdownLinkPreview         Preview the link under cursor content in a
                                  popup window.
                                  Default: `K`

<Plug>MarkdownLinkYankFirstRegister
				  Yank the link under cursor into the register
				  configured by
				  |g:markdown_extras_config|['link_first_register'].
                                  Default: `<localleader>y`
				  Example:
				  >vim
				    g:markdown_extras_config = {}
				    g:markdown_extras_config['link_first_register'] = 'a'
				    nnoremap <buffer> <localleader>ay <Plug>MarkdownLinkYankFirstRegister
<
				  In this example, typing `<localleader>ay` yanks
				  the current link into register `a`.

<Plug>MarkdownLinkYankSecondRegister
				  Yank the link under cursor into the register
				  configured by
				  |g:markdown_extras_config|['link_second_register'].
                                  Default: None

<Plug>MarkdownLinkYankThirdRegister
				  Yank the link under cursor into the register
				  configured by
				  |g:markdown_extras_config|['link_third_register'].
                                  Default: None

<Plug>MarkdownLinkDeleteFirstRegister
				  Delete the link under cursor and store it in the
				  register configured by
				  |g:markdown_extras_config|['link_first_register'].
                                  Default: `<localleader>d`

<Plug>MarkdownLinkDeleteSecondRegister
				  Delete the link under cursor and store it in the
				  register configured by
				  |g:markdown_extras_config|['link_second_register'].
                                  Default: None

<Plug>MarkdownLinkDeleteThirdRegister
				  Delete the link under cursor and store it in the
				  register configured by
				  |g:markdown_extras_config|['link_third_register'].
                                  Default: None

<Plug>MarkdownLinkPasteFirstRegister
				  Paste the yanked link from the register
				  configured by
				  |g:markdown_extras_config|['link_first_register'].
				  References are updated in the destination
				  buffer when needed.
                                  Default: `<localleader>p`

<Plug>MarkdownLinkPasteSecondRegister
				  Paste the yanked link from the register
				  configured by
				  |g:markdown_extras_config|['link_second_register'].
                                  Default: None

<Plug>MarkdownLinkPasteThirdRegister
				  Paste the yanked link from the register
				  configured by
				  |g:markdown_extras_config|['link_third_register'].
                                  Default: None
Tables~
The following mappings can be used for creating mappings related to tables.
Such mappings only work when the cursor is on a table.
To better remember table mappings, the default settings use capital letters.
Cell-edit helpers (`<Plug>MarkdownTableChange` and
`<Plug>MarkdownTableAppend`) only support regular table geometry (single-row,
single-column cells). They do not support pseudo multirow/multicolumn visual
layouts.

Example of unsupported cell-edit layout:
>md
| a    |    a     |
|------|------|---|
|      | a    | a |
|      |      |   |
| a    |------|---|
|      | a    | a |
|------|------|---|
<
In such cases, edit the text manually and use table formatting only for visual
preservation.

<Plug>MarkdownTableAppend	  Append text to the current cell.
                                  Default: `<localleader>A`

<Plug>MarkdownTableChange	  Change the text  of the current cell.
                                  Default: `<localleader>C`

Inside the cell-edit popup, you can paste register contents with `CTRL-R`
followed by a register name (e.g. `CTRL-R "` for the unnamed register,
`CTRL-R +` for the clipboard, `CTRL-R 0` for the yank register). This mirrors
Vim's built-in insert-mode `CTRL-R` behaviour.

<Plug>MarkdownTableFormat	  Format table.
                                  Default:
				   - normal mode: `<localleader>F`
				   - insert mode: `<bar>`

<Plug>MarkdownTableInsertRowDelimiter
				  Insert row delimiter.
                                  Default: `<localleader>_`

<Plug>MarkdownTableSumBlock	  Sum all the numbers in the visual selection
				  and display the result in the command line.
                                  Default: `<localleader>S`

Misc~
<Plug>MarkdownToggleCheck         Toggle checkbox in to-do lists.
                                  Default: `<localleader>x`


==============================================================================
LIMITATIONS                                       *markdown-extras-limitations*


Nothing is perfect, and this plugin is no exception. Here are some known
limitations:

- Markdown is not a regular language, yet many features rely on regular
  expressions. This means there will always be edge cases where some features
  fail. Properly parsing non-regular languages requires more advanced tools
  like Tree-sitter. However, I personally don't believe it's worth "punishing"
  all use cases with slower, more memory-hungry solutions just to handle rare
  edge cases. The choice here is to favor efficiency and speed for the
  majority, rather than striving for exhaustive coverage.

- The plugin leans toward using reference-style links with numeric
  identifiers. You can try using strings as identifiers, but I can't guarantee
  everything will work as expected.

- The link management system depends on a special comment:
  `<!-- DO NOT REMOVE vim-markdown-extras references DO NOT REMOVE -->` This
  comment must be unique and present. Trying to locate links scattered
  randomly throughout the buffer using regular expressions would likely run
  into the same problems mentioned in the first point.
